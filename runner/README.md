# Numen execution runtime

The broker is the trusted Engine control plane. Production application and generated workloads do not receive its Docker socket. It accepts only the fixed API in `docs/implementation-contract.md`; unknown launch fields, unsupported profiles, unsafe paths, remote JSON-schema references, excessive limits and invalid outputs are rejected. `X-Broker-Token` authenticates every control and credential route.

## Images and checks

Agent packages are npm-locked: Pi 1.0.0, Claude Code 2.1.288 and Codex 0.160.0. Command Code provider 0.7.3 is loaded only when the resolved profile explicitly enables it. The Pi image repairs upstream brace-expansion5.0.9 to the integrity-verified compatible5.0.12 tarball, repairs its actual nested shrinkwrap/locks, and routes the exact hash-verified compiled CLI entry point to the fixed module; details and advisories are in `dependency-patches.lock.json`. Post-repair npm audit must pass during image build. Python dependencies use `uv.lock`; base images use immutable multi-platform digests. Trail of Bits audit-context-building 2.0.2 is vendored with attribution, CC-BY-SA-4.0 license and a content hash manifest. The separate workload image tags are `numen-pi`, `numen-claude`, `numen-codex`, `numen-probe`, and `numen-lab`, all `:0.1.0`.

```sh
scripts/compose.sh --profile images build
scripts/compose.sh --profile test run --build --rm runner-tests
scripts/compose.sh --profile test run --build --rm runner-runtime-tests
```

The last command explicitly enables real Engine tests with `NUMEN_DOCKER_TESTS=1`; it does not silently substitute fixtures. Its trusted test driver receives Engine control and uses the `runtime-tests` instance label. Production broker cleanup is scoped to `NUMEN_RUNNER_INSTANCE`, normally the Compose project name. Only integration tests make a credential-free CONNECT to `api.openai.com`; no authenticated inference or production target is used.

## Boundary

Each workload runs as UID/GID10001 with a read-only image, dropped capabilities, no-new-privileges, bounded memory/CPU/PIDs/filesystems/outputs and an execution deadline. Validated inputs are copied by a fixed, credential-free staging container into a job volume mounted read-only. Workspaces, caches and temporary files are bounded tmpfs mounts. Outputs are regular files without links, with normalized relative paths, validated JSON results, integrity hashes and aggregate byte limits. Credentials and arbitrary child stderr are not returned in ordinary status/errors/logs.

A `cve_analysis` agent run requests `build`. It then receives a private per-run rootless Docker daemon on its job network at `tcp://docker:2375`, a disk-backed writable workspace, raised process/memory/output limits, a shell (Codex workspace policy, Claude `Bash`, Pi `numen_shell`), `git`, and proxy access to source, package and image registries. The daemon has its own egress network so builds can install dependencies. The host Engine socket is still never shared with any workload, the agent container stays nonroot with a read-only image and dropped capabilities, and the daemon container holds no credential. The daemon container is privileged because nested containers require it on Engine 20.10 without cgroup delegation; treat a build run as code execution with internet access on the operator's behalf, and note that its daemon, images, containers and workspace are destroyed with the run.

Workloads join only an internal job network. A credential-free per-job proxy has separate egress and allows CONNECT only to the selected provider's fixed TLS hosts on443. Disregarding proxy configuration does not grant direct egress. Target reads use GET/HEAD through an expiring token, explicit origins, `request_budget`/`max_requests`, response/aggregate byte budgets, redirect validation and DNS-pinned sockets. Private/link-local destinations are denied unless the exact asset network is explicitly authorized; application/control networks remain denied.

Pi uses bundled source-read/list and output-write tools, with ambient resources/built-in execution tools disabled. Claude uses restricted file tools, explicit settings/MCP sources and a scoped target MCP tool. Codex derives native permission profiles from `:read-only` for triage and `:workspace` for report/artifact generation, denies tool reads of `/home/job` and excludes provider credentials from shell inheritance. Input mounts remain read-only in both policies. Codex alone uses a narrow Moby20.10.22-derived seccomp adjustment for nested native namespaces; other profiles use Engine default seccomp. Native-policy failures are explicit failures. Codex/Claude structured CLI output uses a fixed `result_json` string envelope, then validates the decoded object against the application schema; this supports application evidence objects without weakening validation or relying on a provider's unrestricted-object schema dialect.

## Connections and native cache ingress

Pi catalogs come from the pinned SDK/provider extension and are intersected with the account's authenticated provider model list. Codex uses paginated native app-server `model/list`, plus API account model access for API-key mode. Claude uses the authenticated model endpoint. Effort values are retained from the runtime/provider metadata; unsupported selected models/efforts fail before inference. Missing usage is `null`.

Codex native setup uses `login --device-auth`. Claude native setup uses `claude auth login --claudeai` in its manual flow: the workload emits only the authorization URL, then waits for the operator's code. The worker relays the code to `POST /internal/runs/{id}/login-input`, which keeps it in broker memory only. The engine writes it into the workload's private home through exec stdin (never argv or environment), and the workload forwards it to the CLI's stdin. Command Code native setup runs the pinned plugin's `/login` through pi's `ModelRuntime.login` (`pi-commandcode-login.mjs`): it emits only the Studio URL, skips the localhost callback that cannot reach the container, and reads the pasted API key over the same login-input channel. The plugin validates the key with `/alpha/whoami`, pi stores it in its private `auth.json`, and later jobs pass it to the plugin as `COMMAND_CODE_API_KEY`. Login events contain only the native verification URI/device code and code-submission state. Pi native OAuth for other providers is explicitly unsupported by this runtime. Claude API keys and protected imported Claude native caches have separate execution paths. Actual account eligibility, OAuth model-endpoint access and native provider/proxy inference compatibility require operator credentials and remain unverified without them.

New/refreshed native caches use private ephemeral files and a fixed Engine exec transport inside the workload's mount namespace. The transport validates a bounded regular file and keeps its private response separate from Docker's main stdout/stderr logs. The broker retains the cache in memory for ten minutes after authoritative completion (kept available while cleanup is pending). A changed cache sets `credential_updated:true` in the ordinary run response, including failed native runs when refresh completed. The vault consumer fetches it with authenticated `GET /internal/runs/{id}/credential`, revision-fences encrypted ingestion, then deletes it with `DELETE` after commit. Ordinary `result`, outputs and events omit cache values. Plaintext temporary state is removed with the workload; broker restart never restores plaintext caches.

## Lab bundles

Artifact upload does not build anything. Explicit verification requires `poc.py`, `report.md` and `vulnerable-app/Dockerfile` plus local application files. The initial verifier accepts declarative materialization (`FROM`, local `COPY`, `WORKDIR`, nonroot `USER`, `ENV`, `EXPOSE`, JSON/runtime `CMD`/`ENTRYPOINT`, `LABEL`). It rejects executable `RUN`, remote `ADD`, mount/build flags and floating bases. Use the bundled `numen-lab:0.1.0`, or an approved Python/Node/PHP/nginx library base pinned by digest. Prerequisites/dependencies must already be in the base or supplied context. Uploaded originals are preserved; unsupported bundles remain downloadable and unverified.

The application then starts nonroot on an isolated network at `http://application:8080`. Only its PoC verifier shares that network; neither gets provider/application credentials or external egress. Observed results retain the built image digest, exit code and bounded log. A nonzero PoC is `status:not_reproduced, verified:false`; successful recording of that result never means successful reproduction. Cancel/timeouts/restarts remove owned containers, volumes, networks and job images. A failed cleanup keeps the run nonterminal (`cancelling`, `cleanup_pending`), preserves its pending result/error privately, retries reconciliation, and blocks new execution with503. A terminal status is published only after actual owned-resource cleanup succeeds. Interrupted work cannot falsely succeed or claim it stopped while Engine availability is unknown. Authenticated `GET /internal/attempts/{attempt_token}` resolves lost submit acknowledgements; explicit `{run_id:null,status:"absent",reconciled:true}` is returned only after reconciliation, while503/404 cannot prove absence.
